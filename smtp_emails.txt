SMTP email flows (ZETOM project)
===============================

Source of sender address
------------------------
All SMTP emails use the sender address from settings.SMTP_USER (env SMTP_USER). If SMTP_USER
is empty, email sending short-circuits (no message is sent). This applies to both plain
emails and emails with attachments/HTML bodies.

Emails sent via SMTP
--------------------
1) Contact form submission: confirmation to the requester
   - From: settings.SMTP_USER (env SMTP_USER).
   - To: contact form "email" field (the requester email).
   - Subject: "Nowa wiadomość z formularza kontaktowego".
   - Message body (plain text): includes full name, phone, email, company, company name,
     request ID, access token, token expiration, and the original message text.
   - Trigger/reason: user submits the public contact form successfully; after saving the
     message and generating an access token.
   - Code: contact/views/public.py calls send_contact_email() when SMTP_USER is set;
     send_contact_email() builds the subject/body in contact/services/email_service.py.

2) Contact form submission: internal notification to company recipients
   - From: settings.SMTP_USER (env SMTP_USER).
   - To: recipients from settings.COMPANY_NOTIFICATION_RECIPIENTS for the message.company
     key, or "default" fallback list.
   - Subject: "Новая заявка для проверки".
   - Message body (plain text): includes a link (COMPANY_NOTIFICATION_LINK or provided
     request panel link), plus requester full name, phone, email, company, company name,
     and the message content.
   - Trigger/reason: user submits the public contact form successfully; the system sends
     internal notifications after saving the message and generating an access token.
   - Code: contact/views/public.py calls send_company_notification(); content assembled in
     contact/services/email_service.py.

3) Admin user credentials / password delivery
   - From: settings.SMTP_USER (env SMTP_USER).
   - To: admin user email (AdminUser.email).
   - Subject: "Your ZETOM admin panel access".
   - Message body (plain text): includes greeting, notice about admin access, the email,
     a temporary password/token, optional role label and departments, and a reminder to
     change the password after first login.
   - Trigger/reason:
       a) Admin settings (admin panel) create or update admin users with a new or changed
          password/token (including autogenerated token).
       b) Admin panel reset password action for another admin user.
       c) Admin profile password change (self) in the admin panel.
   - Code: send_admin_user_credentials() in contact/services/email_service.py; queued via
     _queue_credentials_emails() in contact/views/admin.py for the actions above.

4) Manual email from admin panel (with optional attachment/HTML)
   - From: settings.SMTP_USER (env SMTP_USER).
   - To: "to_email" field in the admin panel email form.
   - Subject: admin panel form "subject".
   - Message body:
       - Plain text: message text, optional quoted text, and a ZETOM signature block
         composed from the form fields.
       - HTML: rendered from templates/emails/zetom_theme.html with inline images.
       - Optional file attachment if provided in the form.
   - Trigger/reason: admin user submits the email composer form in the admin panel.
   - Code: _handle_email_form() in contact/views/admin.py calls send_email_with_attachment()
     in contact/services/email_service.py after assembling the body and inline images.

Notes for future routing control
-------------------------------
- All outbound emails are ultimately sent via _send_message() in contact/services/email_service.py,
  which uses settings.SMTP_USER as the From address and connects to SMTP_SERVER/SMTP_PORT.
- To implement centralized routing changes, consider consolidating recipient overrides or
  address remapping in email_service._send_message() or a wrapper around _send_plain_email()
  and send_email_with_attachment().
